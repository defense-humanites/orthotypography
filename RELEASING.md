# Releasing orthotypography

Publication is disabled until the first prerelease is explicitly approved.

Both registries use `@orthotypography/core` and the version declared in
`deno.json`. JSR publishes the TypeScript source directly; npm receives the ESM
package generated by `@deno/dnt`.

Before enabling publication:

1. create and link the package on JSR;
2. add a granular npm token with bypass 2FA as the `NPM_TOKEN` secret in the
   `release` environment for the first npm publication;
3. protect the GitHub `release` environment and restrict its tags;
4. leave `PUBLISH_ENABLED` absent or equal to `false`.

An npm package is created by its first successful `npm publish`; it does not
need to be reserved beforehand. Trusted publishing cannot be configured until
the package exists, so the workflow exposes `NPM_TOKEN` only to the npm publish
step for this bootstrap release. After the first publication, configure
`.github/workflows/publish.yml` and the `release` environment as the package's
trusted publisher, then remove `NPM_TOKEN`. npm will use OIDC automatically on
subsequent releases.

For a prerelease, run `deno task check`, `deno task test`,
`deno task publish:check`, and `deno task npm:check`; tag the exact version with
a `v` prefix; then enable `PUBLISH_ENABLED` only for the authorized publication
window.

## Partial publication recovery

The workflow resolves the exact version independently on JSR and npm before
publishing. A version already present is skipped; only a missing registry is
published. The final step waits for both registries to expose the version and
fails if the release remains incomplete.

To resume a partial publication, rerun the failed workflow. If the original run
is no longer available, dispatch `Publish` manually with the existing release
tag. The tag must still equal `v` followed by the version in `deno.json`, and
`PUBLISH_ENABLED` must be `true`. Never increment the version merely to recover
the registry that is missing.

Before resuming, verify that the existing version belongs to this release. The
workflow treats an exact version found on a registry as immutable and
authoritative; it does not overwrite or replace it.
